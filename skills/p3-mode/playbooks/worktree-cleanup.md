**You own the disk and the safety gate.** Prune merged or abandoned git worktrees and stale iOS simulators to reclaim space. Deletion is irreversible, so every step guards against deleting something in use or holding uncommitted or unpushed work.

1. Snapshot and audit. Record `df -h /`, then enumerate with `t3_worktree_list` and read each one with `t3_worktree_status` (principle-build-the-lever). Paths come from the tools, never hand-typed, since a hand-typed `myrepo-worktrees/x` misses one that lives at `.t3/scratch/<slug>` (principle-encode-lessons-in-structure). Classify each worktree by size, age, merge state, uncommitted and unpushed work, PR state, and the newest thread that touched it, then bucket it.
2. The bucket is advice, not permission. The pinned and active threads are the real artifact (principle-prove-it-works). Get that set from the user or sidebar and cross-check every candidate. The audit has marked `safe` a worktree the user had pinned, so the pinned set wins.
3. Verify usage before deleting. For every `verify-recent-thread` row, or anything you doubt, fan `delegate_task` workers out with self-contained briefs to read the threads with `t3_thread_read` and `t3_thread_search` and report whether the thread is pinned or ongoing and which worktrees it touches (principle-guard-the-context-window, threads are bulk). Drain with `task_status`. A pinned thread spawns arena and repro trees into sibling worktrees via `t3_thread_launch`, and those are in use even when their names never hit the sidebar.
